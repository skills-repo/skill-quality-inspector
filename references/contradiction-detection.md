# 矛盾点检测方法论（contradiction-detection）

> 一个技能仓库最容易"说一套做一套"的地方：README 改了 SKILL.md 没改、references 加了脚本没登记、合并后规则打架。本篇给出矛盾的类型学与修复 SOP。

## 一、矛盾类型学

| 类型 | 表现 | 严重度 | 脚本能否抓 |
|------|------|--------|------------|
| 数字对账失败 | README 写"5 个子技能"但 `skills/` 只有 4 个 | 阻断 | ✅ `contradiction_scan.py` |
| 断链 | playbook 写 `scripts/x.py` 但磁盘无此文件 | 阻断 | ✅ |
| 重复标题 | 同一文件出现两次同名 `##` | 警告 | ✅ |
| 术语漂移 | "Level A" 与 "A 级"、"路由表" 与 "能力索引" 混用 | 警告 | ⚠️ 启发式 |
| 规则冲突 | 两篇 references 对同一事项口径相反 | 阻断 | ❌ 需人工 |
| 悬空路由 | 根 SKILL.md 路由行指向不存在的路径 | 阻断 | ✅ `quality_audit.py` |
| 孤儿文件 | references/scripts 存在但根 SKILL.md 未索引 | 警告 | ✅ |

## 二、检测启发式（脚本实现）

1. **数字对账**：在 README/SKILL.md 里用正则抓"(\d+)\s*(个子技能|篇 references|个脚本|个 assets)"，与实际目录 `len(os.listdir)` 比对。
2. **断链**：仅校验真正的 Markdown 链接 `[文本](references|scripts|assets/...)`，对命中路径逐个 `os.path.exists` 校验（示例/说明性路径不再误判为断链）。
3. **重复标题**：解析每个 `.md` 的 `##`/`###` 标题，统计文本重复。
4. **术语漂移**：维护一张"规范词 → 同义写法"映射表（如 `Level A → [A 级, A级, LvA]`），扫描非规范写法。映射表放在本仓库 `assets/`（待补时可空跑）。

## 三、修复 SOP

```
1. 跑 contradiction_scan.py --json → 得到 findings[]
2. 阻断项优先：
   - 数字对账失败 → 优先"补齐产物让文案成真"（如真有第 5 个子技能就建出来），
     而非把文案数字改小糊弄（D35 实证：改小口径会掩盖真缺陷）
   - 断链 / 悬空路由 → 补文件或改路径，二选一；改路径注意不要碰 lock 锁定路径
3. 警告项：
   - 重复标题 → 删冗余或改名区分
   - 术语漂移 → 选规范写法全库替换，并在根 SKILL.md/AGENTS.md 固定术语表
4. 规则冲突（人工）→ 读懂两篇，确定口径，一处改一致，另一处加交叉引用
5. 回归：重跑脚本 + 架构门禁，确认 findings 归零
```

## 四、典型坑

- **"整体覆写 README"陷阱（D32）**：用 superpower 风格 README 整文件替换 legacy README，会把安装命令段与子技能清单一并删掉 → 先抄出旧安装命令再改。
- **静默失配**：大正则匹配失败时可能不报错只输出 0（D35）→ 复杂匹配拆多条小正则，每条只管一个字段。
- **改了文案没改产物**：数字对账的本质是"文案 vs 实际"，修哪边都要让两边重新一致，别留半截。
